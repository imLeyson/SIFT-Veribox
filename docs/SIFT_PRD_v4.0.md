## 0. 这版 PRD 解决什么问题

SIFT 由一条固定的“问答到单主题”流程升级为一张可持续生长的设计推演画布。用户从新建项目开始，可以创建多个 0 简报、1 视觉判断、2 策略基准和 3 主题卡片；任意卡片都可以被复制、分支、打标签、放入图片或便签，并通过连线把多个判断合成为新的内容。用户可以在几个小时的头脑风暴后，从大量主题中标记喜欢的方向，再把多个主题连接到空白卡片，继续生成新的策略、主题、灵感检索或画面生成内容。

这版产品的核心不是把用户送进一条必须完成的流程，而是帮助团队维护一张**有来源、有分支、可回溯、可协同的视觉判断网络**。AI 负责整理、比较、合成和提出下一步，设计师保留选择、否定、组合和暂停的权利。

### 0.1 设计原则

1. **画布是工作主体**：卡片、图片、标签和连线共同构成项目记忆。
2. **流程可分支**：0、1、2、3 卡片都可以有多个实例，不要求唯一主路径。
3. **连接才产生关系**：卡片之间的连线表达“基于、比较、融合、深化、引用”等语义。
4. **生成内容必须可追溯**：每张生成卡片都能看到输入卡片、输入版本、生成时间和生成方式。
5. **主题自适应生成**：主题名称、英文标签和视觉维度根据 Brief、判断和已有上下文变化，不使用固定的三套模板词。
6. **AI 不替用户拍板**：策略顾问和合成卡片都先给出可编辑草案，不能静默覆盖用户内容。
7. **协同状态可见**：用户知道谁在线、谁正在编辑什么、自己的修改是否已经同步，以及发生冲突时该如何处理。

## 1. 产品定位与边界

### 1.1 产品定位

SIFT 是面向包装、品牌、产品、CMF 和数字产品设计团队的视觉策略与方向推演工作台。它把模糊 Brief、视觉判断、策略基准、设计主题、灵感检索、参考图片和生成画面放在一张可协同的无限画布上，帮助团队从大量可能性中形成可讨论、可解释、可继续验证的方向。

### 1.2 目标用户

| 用户 | 主要任务 | 需要的帮助 |
| --- | --- | --- |
| 设计师 | 发散、比较、组合视觉方向 | 快速生成差异化假设，保留灵感上下文 |
| 设计总监 | 评审和收敛方向 | 看见来源、分支、异议和选择依据 |
| 品牌/产品负责人 | 提供业务判断和约束 | 在不读完整设计过程的情况下参与关键决策 |
| CMF/工程成员 | 验证材质、工艺和现实约束 | 读取策略链路，补充图片、标签和限制 |
| 多人项目小组 | 同步探索结果 | 共享房间、在线状态、光标、操作历史和冲突处理 |

### 1.3 产品边界

SIFT 负责前期方向探索、策略表达、灵感检索组织和概念画面辅助。它不承诺最终生产、打样、工程验收、合规审查或成品交付。画面生成用于讨论视觉假设，不作为量产效果图或工程尺寸依据。

## 2. 核心对象与画布模型

### 2.1 项目与画布

一个项目包含一个或多个画布。项目支持命名、复制、归档、恢复、分享和导出。画布保存卡片、连线、位置、折叠状态、标签、协同房间信息和版本历史。

画布中的内容分为三类：

- **流程卡片**：0 简报、1 视觉、2 策略、3 主题、4 视点推进、灵感检索。
- **创作卡片**：空白合成卡、设计便签、参考图片、画面生成。
- **辅助对象**：标签、评论、收藏、分组、关系线、协作者光标和选区。

画布不要求从左到右完成，也不要求所有节点连接成一条链。系统允许多棵树、多个孤立卡片和跨分支连接，但必须通过来源和关系类型保留上下文。

### 2.2 节点类型

| 编号 | 卡片 | 用户目的 | 主要输出 | 当前状态 |
| --- | --- | --- | --- | --- |
| 0 | 简报 | 记录目标、受众、载体、约束和参考 | Brief 与待确认信息 | 已有 |
| 1 | 视觉判断 | 对比视觉两极、记录偏好或暂不确定 | 视觉判断与回答来源 | 已有 |
| 2 | 策略基准 | 固化意图、优先级、避免项、判断标准 | 可引用的策略状态 | 已有 |
| 3 | 主题 | 根据上游内容形成适合当前项目的主题 | 主题名、画面描述、优势、风险、视点 | 已有，需继续去模板化 |
| 4 | 视点推进 | 把一个主题拆成可观察的视觉问题 | 视点、观察重点、验收条件 | 已有 |
| 灵感检索 | 连接后直接进行“跨平台灵感检索” | 跨平台检索词、来源和搜索入口 | 已有，需保持直达 |
| 空白卡 | 选中的主题或其他内容的合成容器 | 新的主题、策略或检索方案 | 已有，需明确合成协议 |
| 画面生成 | 将主题、图片和文本转为概念图 | 多个候选画面、提示词和参数 | 已有 |
| 参考图片 | 放置用户上传、粘贴或拖入的图片 | 图片、来源、备注和标签 | 已有 |
| 设计便签 | 保存灵感、评审意见和临时判断 | 可编辑文本和颜色标签 | 已有 |
| 策略顾问 | 对项目全局或选中卡片提问 | 建议、比较、总结和可执行动作 | 已有，需加强引用和操作确认 |

### 2.3 关系类型

连线不能只代表“相连”。用户创建连线时可以选择或由系统推断关系：

- **基于**：下游内容引用上游内容。
- **比较**：把两个方向放在同一问题下对照。
- **融合**：合并多个主题的优势，生成新主题。
- **深化**：沿着一个主题继续生成视点、策略或画面。
- **参考**：图片、便签或外部资料为卡片提供证据。
- **反例**：记录不采用的方向以及原因。

默认操作保持轻量：用户可以先画线，再点击目标卡片上的“生成”。系统不能因为用户刚完成连线就自动消耗模型请求或自动覆盖卡片。

## 3. 端到端用户流程

### 3.1 新建项目与初始画布

1. 用户点击“新建项目”。
2. 系统创建空白画布，生成一个 0 简报卡片，也允许用户继续添加更多 0 简报卡片。
3. 用户输入 Brief、上传或粘贴参考图片，系统给出缺失信息提示，但不强迫补齐所有字段。
4. 用户可以点击“开始收敛”，生成 1 视觉卡片和 2 策略卡片；也可以直接添加 1、2、3 或创作卡片。

### 3.2 0 到 3 的可分支流程

标准流程为：

```text
新建项目
  └─ 0 简报（可多个）
      ├─ 1 视觉（可多个分支）
      │   └─ 2 策略（可多个版本）
      │       └─ 3 主题（可多个主题）
      ├─ 3 主题（用户手动创建或直接生成）
      └─ 创作卡片、灵感检索、画面生成
```

每个阶段都支持以下操作：

- 添加同类型卡片，形成平行方案。
- 复制卡片，保留来源并创建可独立编辑的版本。
- 将卡片连接到空白卡或其他工具卡片。
- 折叠卡片，仅显示标题、标签、状态和来源。
- 暂停、归档或标记为反例，不删除历史依据。

### 3.3 主题筛选与合成

当用户经过多轮头脑风暴后得到大量主题：

1. 用户给主题卡片添加“喜欢”“待评审”“反例”“灵感”等标签。
2. 用户打开“精选视图”，只查看已标记的卡片及其来源链路。
3. 用户新建空白卡片，将一个或多个喜欢的主题连入空白卡片。
4. 用户选择生成目标：新主题、策略比较、灵感检索、视点推进或画面生成。
5. 系统读取所有上游卡片的当前版本、来源关系、图片摘要和标签，生成可编辑的新内容。
6. 新卡片必须显示“由哪些卡片生成”，并允许用户展开查看每个输入的贡献。

合成数量规则：

- 1 个主题连接到空白卡：生成该主题的变奏、深化或新视点。
- 2 个主题连接到空白卡：生成比较结果或融合主题。
- 3 个及以上主题连接到空白卡：先生成共同点、冲突点和选择建议，再由用户确认是否融合。
- 输入包含 0、1、2 卡片时：优先生成策略或问题，不直接伪造主题。
- 输入包含图片时：图片只作为视觉证据，系统必须标记“图片观察”与“模型推断”。

### 3.4 灵感检索

灵感检索卡片连接后，直接进入“跨平台灵感检索”，取消中间的“选择此主题，开始视点探索”步骤。检索卡片展示：

- 当前检索目标和对应主题。
- 结构、材质、气质、场景等检索维度。
- 平台分工、搜索词、去噪词和搜索入口。
- 已打开、已复制、已跳过的来源状态。
- 用户手动添加的发现和图片。

系统不得把搜索结果数量当作完成度。用户可以从任何检索卡片继续生成主题、便签、图片或画面生成卡片。

### 3.5 画面生成

画面生成卡片可以连接到主题、策略、图片、便签或空白卡。用户可编辑提示词、比例、风格和参考图权重，生成多个候选画面。每张候选画面需记录：

- 使用的输入卡片与图片。
- 完整提示词和负面提示词。
- 生成时间、模型、比例和风格参数。
- 用户选择、淘汰或继续迭代的结果。

画面生成服务异常时保留用户输入，不丢失卡片和已生成候选。

## 4. AI 能力要求

### 4.1 主题生成必须根据前置内容自适应

主题生成输入包括 Brief、已确认的视觉判断、策略基准、连接关系、图片观察、用户标签和已有主题。模型需要根据这些内容选择合适的主题维度，例如材质、形态、叙事、色彩、空间、工艺、交互或品牌语气。

主题输出至少包含：

- 主题名称与可选英文短标。
- 一句话视觉主张。
- 具体画面描述。
- 主要视觉母题。
- 与 Brief 的来源对应。
- 适合继续验证的视点。
- 可能的冲突、风险和不确定项。

禁止固定生成“物性本真、诗意人本、工业精密”等预设类别。模型可以偶尔使用相似词汇，但必须由输入语义触发，不能按固定顺序、固定数量或固定模板填充。

### 4.2 策略顾问

策略顾问是全局上下文助手，不是另一条强制流程。它可以：

- 总结当前画布和选中分支。
- 比较多个主题的差异、共性和风险。
- 指出某个判断缺少哪些证据。
- 建议连接哪些卡片或创建什么类型的新卡片。
- 将对话结果写入便签、策略卡或空白卡，但必须经过用户确认。
- 给出可撤销的批量操作预览，例如“将 4 张主题标记为待评审”。

每条建议应引用相关卡片和连线；没有来源的内容必须标记为推测。

### 4.3 不再保留的交互

以下内容从产品主流程中移除：

- 主题卡片上的“追问”入口。
- “选择此主题，开始视点探索”按钮。
- “主推方案”显示。
- 固定的主题模板类别和固定主题顺序。
- 连接灵感检索卡片前的额外确认步骤。

这不代表删除所有提问能力。提问由 1 视觉卡片、策略顾问或用户明确创建的问答卡承载；主题卡片保持为可阅读、可连接、可复制、可合成的设计对象。

## 5. 多人协同体验

### 5.1 进入协同房间

- 用户可以通过邀请链接或房间 ID 加入。
- 进入前显示项目名、房间名和当前在线人数。
- 用户首次进入设置姓名、头像颜色和角色。
- 角色仅用于协作识别，不限制查看；涉及删除、批量操作和导出时使用项目权限控制。

### 5.2 协同状态

顶部协同入口应明确显示：连接中、已连接、需同步、离线保存或错误。用户可以看到在线成员、当前所在卡片、光标和最近活动，并可点击成员头像跟随其视角。

### 5.3 同步与冲突

所有会改变画布的操作都带有：`operationId`、`roomId`、`userId`、`baseRevision`、`createdAt` 和目标对象版本。客户端要求：

- 操作幂等，重复到达不能重复创建卡片或连线。
- 服务端按序返回操作，客户端处理迟到操作时不覆盖较新的本地版本。
- 同一字段同时修改时显示冲突提示，提供保留本地、采用远端和合并文本三个选项。
- 删除是可恢复的软删除，避免协作者误删后无法找回。
- 离线时进入本地队列，重新联网后按顺序重放，并显示重放结果。
- 快照只用于初始化和恢复，不能作为长期的唯一同步机制。

### 5.4 协同权限与安全

P0 需要补齐持久化房间和权限边界。当前服务端内存房间适合演示，生产环境需要：

- 持久化项目、房间、成员、操作日志和快照。
- 邀请链接可设置有效期、只读或可编辑权限。
- 房间成员可以被移除，邀请可以失效。
- 图片和生成结果按项目隔离，不能通过猜测 URL 访问其他项目。
- 记录关键操作审计：加入、删除、导出、权限变化和冲突处理。

## 6. 功能需求清单

### P0 必须完成

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P0-01 | 多节点画布 | 同一项目可同时存在多个 0、1、2、3 卡片，刷新后保留位置、连线、内容和标签 |
| P0-02 | 空白卡合成 | 用户连接主题到空白卡并选择生成目标后，生成卡片显示完整来源和可编辑草案 |
| P0-03 | 自适应主题 | 不出现固定三套主题模板；主题内容与 Brief、策略、图片和用户选择存在可追溯对应 |
| P0-04 | 直达灵感检索 | 灵感检索卡片连接后可直接进入“跨平台灵感检索”，不再出现额外主题选择步骤 |
| P0-05 | 清理旧入口 | 主题卡片没有追问入口、视点探索按钮和主推方案标签 |
| P0-06 | 协同一致性 | 两个浏览器同时编辑同一房间时，卡片、连线、移动、标签和图片状态最终一致；重复操作不产生重复对象 |
| P0-07 | 协同持久化 | 服务端重启或请求落到不同实例后，房间内容和成员权限仍可恢复 |
| P0-08 | 可恢复历史 | 用户可以查看、恢复和撤销最近的卡片、连线、标签和合成操作 |

### P1 应完成

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P1-01 | 精选视图 | 按标签筛选喜欢、待评审、反例和灵感，并保留来源链路 |
| P1-02 | 画布导航 | 提供缩略图、搜索、按标签聚焦、按分支折叠和“回到最近编辑” |
| P1-03 | 策略顾问引用 | 每条建议引用卡片；执行动作前展示预览，支持撤销 |
| P1-04 | 资产管理 | 图片有来源、尺寸、上传人、时间、项目归属和删除恢复能力 |
| P1-05 | 导出提案 | 导出当前精选分支、来源关系、主题、检索词、图片和未决项，不导出无关草稿 |
| P1-06 | 评审模式 | 只读展示精选主题、关键依据、反例和待决问题，适合评审会议 |

### P2 可持续优化

- 主题相似度检测与重复提醒。
- 画布分区和分组模板。
- 卡片评论、@成员和评审任务。
- 版本对比和时间线回放。
- 语义搜索“找出所有与某种材质或气质相关的卡片”。
- 外部链接和检索结果的来源收藏。
- 对生成画面进行批注和局部重生成。

```ts
  createdBy: string;
  createdAt: string;
};
```

## 8. 服务与接口要求

当前工程已有 `brief`、`clarify`、`routes`、`platform-plan`、`image-gen`、`global-chat` 和 `collaboration/room` 能力。主题卡片追问接口已移除，v4.0 需要统一为以画布和项目为中心的接口：

- `POST /api/projects`：创建、复制项目。
- `GET /api/projects/:id`：读取项目和画布快照。
- `POST /api/cards`：创建卡片。
- `PATCH /api/cards/:id`：编辑卡片，带版本号。
- `POST /api/edges`：创建关系线。
- `POST /api/synthesis`：按输入卡片和目标类型生成内容。
- `GET /api/synthesis/:id`：读取生成状态、来源和结果。
- `POST /api/collaboration/rooms/:id/operations`：提交幂等操作。
- `GET /api/collaboration/rooms/:id/operations?after=`：读取增量操作。
- `POST /api/collaboration/rooms/:id/snapshots`：创建可恢复快照。
- `POST /api/advisor`：传入选中卡片和画布上下文，返回带引用的建议。

所有写接口必须校验项目权限、对象版本和请求幂等键。模型输出必须先通过 schema 校验，再写入画布。

## 9. 非功能需求

| 领域 | 要求 |
| --- | --- |
| 性能 | 300 张卡片以内拖动和缩放保持流畅；初次打开优先渲染可视区域 |
| 协同延迟 | 正常网络下操作状态在 1 秒内到达其他在线成员；断线后显示明确状态 |
| 可靠性 | 模型失败、图片失败、刷新和短暂断网不丢失已输入内容 |
| 一致性 | 所有协同写操作幂等；不允许重复卡片、重复连线和旧响应覆盖新状态 |
| 安全 | 项目和资产按权限隔离；邀请链接可失效；日志不记录密钥和完整隐私内容 |
| 可访问性 | 键盘可操作、清晰中文标签、状态不只依赖颜色、支持减少动态效果 |
| 可解释性 | AI 内容标记来源、假设和待验证项；合成结果能回溯到输入版本 |
| 可维护性 | 卡片 schema、关系类型和模型提示词版本化；迁移失败可回滚 |

## 10. 验收场景

### 场景 A：多条 Brief 分支

用户创建两个 0 简报，一个关注材质，一个关注品牌叙事；分别生成多个 1、2、3 卡片。两个分支可以互不干扰，也可以连接到同一空白卡，生成“共同策略比较”。刷新页面后所有卡片和关系保持不变。

### 场景 B：从喜欢的主题继续探索

用户经过数小时探索后，给 5 张主题卡片标记“喜欢”。打开精选视图后只看到这 5 张及必要来源。将其中 2 张连接到空白卡，选择“新主题”，生成一个不使用固定模板词的复合主题；结果卡片显示两个输入主题、融合理由、冲突和下一步视点。

### 场景 C：直达灵感检索

用户从任意主题连接灵感检索卡片。卡片直接展示“跨平台灵感检索”，并生成按结构、材质和气质拆分的关键词。用户不需要先点击“选择此主题，开始视点探索”。

### 场景 D：主题到画面

用户将主题和参考图片连接到画面生成卡片，修改提示词和比例，生成 4 个候选结果。选择其中 1 个后继续连接到便签或策略卡片，所有候选和参数可回看。

### 场景 E：多人同时编辑

两名用户加入同一房间：一人移动并标记主题，另一人编辑策略卡并上传图片。双方在 1 秒内看到对方的光标和修改。两人同时编辑同一段文本时，系统显示冲突并提供合并选项；刷新、重连或服务实例切换后内容不丢失。

### 场景 F：策略顾问辅助评审

用户选中 3 张主题和 2 张图片，询问“这三张方向最主要的差异是什么”。策略顾问引用具体卡片，给出比较表和待验证问题。用户确认后，系统创建一张评审便签；未确认前不自动修改原卡片。

## 11. 关键指标

- 新建项目后 10 分钟内成功创建至少 2 个分支的比例。
- 项目中被连接、复制或合成的卡片比例。
- 用户从主题进入灵感检索的平均操作步数，目标不超过 1 次确认。
- 生成主题中包含真实 Brief 来源和用户判断来源的比例。
- 多人房间操作最终一致率、冲突恢复成功率和重复对象率。
- 精选视图使用后导出提案或评审模式的转化率。
- 模型失败、图片生成失败和断线情况下的内容保留率。

## 12. 研发优先级与里程碑

### 里程碑一：画布关系与内容可信度

完成 P0-01 至 P0-05，统一卡片、关系、来源和合成记录，移除旧入口，并验证多分支和主题自适应生成。

### 里程碑二：多人协同可靠性

完成 P0-06 至 P0-08。优先解决持久化、权限、幂等操作、版本冲突、离线队列和恢复历史，再继续增加评论和评审功能。

### 里程碑三：评审与资产管理

完成精选视图、画布导航、策略顾问引用、图片资产信息和提案导出，让长时间探索后的项目可以被快速整理和复盘。

## 13. 需要特别关注的产品风险

1. **卡片数量增长后找不到内容**：必须优先做精选视图、搜索、分组、折叠和来源导航。
2. **AI 合成看起来合理但无法解释**：没有来源和输入版本的生成内容不得进入正式提案。
3. **多人协同只在单实例演示有效**：当前内存房间适合原型，生产环境必须使用持久化存储或实时协同服务。
4. **过度自动化打断设计判断**：连线不应立即触发高成本生成；生成目标和写入原卡必须由用户确认。
5. **画面生成改变产品定位**：所有画面都要标注为概念探索，主叙事仍然是视觉策略和方向判断。
6. **主题模板重新回潮**：要通过提示词约束、输出校验和重复检测共同避免固定类别占据主题列表。

## 14. Definition of Done

一项功能只有同时满足以下条件，才算完成：

- 用户在真实画布上能完成完整操作，而不是只有 API 或 Mock 通过。
- 卡片、连线、标签、图片和生成结果刷新后可恢复。
- 产生 AI 内容时可看到来源、假设和输入版本。
- 多人房间中可观察到在线状态、操作同步和冲突反馈。
- 失败、断网和重复请求不会丢失或重复写入内容。
- 关键入口符合当前产品决策：主题卡片不追问、不显示主推方案，灵感检索直达跨平台检索。
- 新增能力有明确的 P0/P1 优先级、验收场景和回滚方式。
