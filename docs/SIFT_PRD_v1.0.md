# SIFT 产品需求文档

**版本：** v1.0
**状态：** 已上线，对应生产实现
**产品名：** SIFT
**Agent：** 视觉研究规划 Agent（Visual Research Planner）
**线上：** https://veribox-mvp.vercel.app
**仓库：** https://github.com/imLeyson/SIFT-Veribox

> SIFT 是一个帮助设计师把模糊 Brief 编排成视觉探索路线和搜索行动的 Agent。

本文由当前已落地产品反写，并吸收原 `Veribox_Exploration_Agent_MVP_PRD_v0.1.md`、设计团队视觉探索流程、以及前期调研录音中的约束。它描述 **v1 必须做什么**，而不是愿景清单。

---

## 1. 背景与问题

设计师拿到 Brief 之后，真正卡住的往往不是「找不到图」，而是：

- 不知道先探索什么
- 不知道用什么顺序探索
- 不知道当前该去哪个平台
- 中英文关键词来回翻译成本高
- 有感觉时难以把感觉变成可执行的搜索动作
- 没想法时容易打开熟悉平台无目的浏览

找图本身不是产品优势（生成图已经又快又便宜）。SIFT 的切口是 **文字与编排**：把任务变成「顺序 + 平台 + 可复制的中英词」，让人带着目的离开产品、去原网站搜。

---

## 2. 产品定位

### 2.1 一句话

面向设计前期的视觉探索 Agent：从 Brief 出发，生成不同探索路线，并按当前步骤动态给出搜索来源与平台化关键词；设计师在无限画布上选择、分支、对话深化。

### 2.2 核心原则

**Agent 负责组织可能性，设计师负责判断和选择。**

- Agent 不替用户决定最终风格
- 最多推荐 1 条路线，推荐 ≠ 自动选择
- 三条路线是三种探索方法，不是三个风格方案
- 搜索计划随当前步骤变化，不是固定排行榜
- 人可以跳过、替换来源，可以返回上一步

### 2.3 明确不是什么

SIFT v1 **不是**：

- 更好的 Pinterest
- 自动抓图 / 自动 Moodboard 工具
- 包装设计全流程操作系统（战略 → 工艺 → 发布）
- 聊天机器人把设计做完

包装、品牌、UI、平面只要仍需前期视觉探索，都可以用。包装流程是验证样本，不是产品围墙。

---

## 3. 目标用户

第一版服务需要做项目前期视觉调研的 **个人设计师**：

- UI / UX、Visual、Brand、Graphic、Product Designer
- 设计专业学生

### 两种进入状态

| 状态 | 用户原话 | 产品行为 |
|------|----------|----------|
| 已有想法 | 「感觉应该比较自然、编辑感。」 | 可输入感觉词，再生成路线 |
| 暂无想法 | 「只知道 Brief 要年轻、有品质感。」 | 不强迫先想关键词，直接生成路线 |

---

## 4. 范围

### 4.1 v1 覆盖

```text
Brief
→ 理解任务（Brief Card）
→ 选择当前状态（已有想法 / 暂无想法）
→ 生成 3 条探索路线
→ 用户选择路线
→ 仅为第一步生成平台搜索计划
→ 画布上复制关键词 / 打开搜索 / 跳过 / 替换 / 更多来源
→ 可切换到路线下一步
→ 画布对话基于选中卡片深化（1–3 张洞察卡）
```

### 4.2 v1 不做

- 网页或图片自动抓取
- Pinterest / 小红书浏览器插件
- 图片上传、识别、分类
- 自动 Moodboard
- AI 出图（含粗预览）
- 本地素材库 / 风格反推报告
- 团队协作、评论、投票
- 登录、权限、数据库
- 移动端专项适配

这些属于后续版本（素材选择、方向形成、Moodboard、协作）。

## 5. 用户流程与状态机

状态必须按顺序推进，不得跳过「当前状态」直接出路线。

```text
brief_input
→ brief_confirm
→ starting_state
→ routes
→ platform_plan
→ canvas_chat（可随时从选中卡片进入，不替代主流程）
```

### 5.1 逐步行为

1. **输入 Brief**
   粘贴自然语言任务。可填示例。

2. **确认 Brief Card**
   Agent 结构化为：Goal、Target User、Known、Unknown、Constraints、Deliverable，以及最多 3 个待确认问题。
   用户可改字段。确认后只生成 **状态卡**，不生成路线。

3. **选择状态**
   - 已有想法：输入若干感觉词后再生成路线
   - 暂无想法：直接生成路线

4. **三条路线**
   展示为画布上的三张卡片。起点必须不同。最多一张标「推荐」。用户点选一套后，未选路线弱化。

5. **平台搜索计划（仅当前步骤）**
   默认 3 个来源，每源 2–4 个关键词（外文必须有中文释义）。
   支持：复制、打开搜索、跳过、替换、更多来源（2–4 个备选）。
   「下一步」为该路线的下一步再生成一张搜索卡，不覆盖上一张。

6. **画布对话**
   读取整张画布、连线、当前焦点。默认长出 1–3 张可执行洞察卡，挂在已有卡片上。不重写主流程，不伪造不存在的上下文。

### 5.2 导航

- **返回上一步**：回到真实上一状态，并移除该步之后生成的卡片（例如从搜索计划回到路线时去掉平台卡）。不得只取消选中。
- **新建探索**：清空会话、画布、对话和本地缓存。

---

## 6. 画布交互需求

主界面是无限画布，不是线性翻页。

| 能力 | 要求 |
|------|------|
| 卡片类型 | 任务输入、Brief、状态、路线、平台搜索、洞察 |
| 拖动 | 拖标题栏移动卡片 |
| 平移缩放 | 拖空白平移；滚轮缩放 |
| 连线 | 从连接点拉线；用户可自建连接 |
| 焦点 | 选中卡片作为对话焦点 |
| 深化 | 选中后可「从这里深化」，或在侧栏发送 |
| 布局 | 新卡片生成后应能看到可点的操作，避免严重重叠导致点不到 |
| 刷新 | 恢复当前探索；loading 与临时错误不恢复 |

## 7. Agent 能力需求

### 7.1 Brief Parser

- 只提取用户明确说出的内容
- 不编造品牌名、成分、包装结构、视觉结论
- 区分 Known / Unknown / Constraints
- 信息不足时最多 3 个待确认问题
- 不输出最终风格方案

### 7.2 Route Generator

- 正好 3 条路线，id 为 `route_01` / `route_02` / `route_03`
- 三种探索方法，不是三个风格名（禁止「自然 / 极简 / 高级」当路线标题）
- 三条起点必须不同（品类、元素、竞品、场景、材质、跨品类等）
- 每条 3–5 步，有明确探索问题、目的、优势、风险
- 最多推荐 1 条；理由必须挂钩 Brief 的未知项

### 7.3 Platform Planner

- 来源从注册表选取，带能力标签：视觉扩散、跨品类参考、完整项目验证、国内语境、品牌官网验证、历史收藏回看
- 排序随当前路线步骤和 Brief 变化，禁止永远同一顺序
- 正好 3 个主来源，角色不同；备选 2–4 个
- 每源 2–4 个可执行关键词；外文有中文释义；中文词的释义写用途，不重复原文
- 不要求用户跑遍所有平台

### 7.4 Canvas Chat

- 先读画布再回答
- 生成新分支，不重做主流程
- `parentId` 必须是已有卡片
- 卡片必须可执行（更窄的词、对照假设、要用户拍板的问题）
- 不替用户做最终视觉判断

### 7.5 运行模式

| 条件 | 模式 |
|------|------|
| 已配置 `LLM_API_KEY` | Live，模型为 `LLM_MODEL`（生产为 gpt-5.6-terra） |
| 未配置 Key | Mock，结构化模板，保证可走通 |

有 Key 时 **禁止** 静默回退 Mock。模型失败须返回可读错误，并保留当前画布。

## 8. 数据契约

所有 Agent API 响应外壳：

```json
{
  "data": {},
  "mode": "live",
  "model": "gpt-5.6-terra"
}
```

### 8.1 Brief

```json
{
  "goal": "string",
  "targetUser": "string",
  "known": ["string"],
  "unknown": ["string"],
  "constraints": ["string"],
  "deliverable": "string",
  "openQuestions": ["string"]
}
```

`openQuestions` 最多 3 条。

### 8.2 Routes

```json
{
  "recommendedRouteId": "route_01" | "route_02" | "route_03" | null,
  "routes": [
    {
      "id": "route_01",
      "title": "string",
      "question": "string",
      "steps": ["string"],
      "purpose": "string",
      "advantage": "string",
      "watchOut": "string",
      "recommendationReason": "string"
    }
  ]
}
```

`routes` 长度必须为 3；每条 `steps` 长度 3–5。

### 8.3 Platform Plan

```json
{
  "goal": "string",
  "sources": [
    {
      "rank": 1,
      "name": "Pinterest",
      "label": "视觉扩散",
      "reason": "string",
      "queries": [{ "query": "string", "translation": "string" }],
      "searchUrl": "string"
    }
  ],
  "alternatives": []
}
```

`sources` 长度 3；每源 `queries` 长度 2–4；`alternatives` 长度 2–4。

### 8.4 Canvas Chat

```json
{
  "reply": "string",
  "cards": [
    { "title": "string", "body": "string", "parentId": "existing-card-id" }
  ]
}
```

`cards` 0–3 张；`parentId` 必须对应已有卡片。

## 9. 接口

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/status` | 返回 `{ mode, model }` |
| POST | `/api/brief` | `{ brief: string }` → Brief |
| POST | `/api/routes` | `{ brief, starting_state, user_initial_idea }` → 3 条路线 |
| POST | `/api/platform-plan` | `{ brief, selected_route, active_step }` → 搜索计划 |
| POST | `/api/canvas-chat` | `{ message, nodes, edges, selectedId }` → 回复 + 洞察卡 |

客户端请求须有超时（约 50 秒），超时或失败不得锁死界面；用户可取消思考。

## 10. 非功能需求

- **可靠性：** 模型调用有明确超时；仅对空响应、网络错误、5xx（不含超时本身）重试一次。
- **状态：** 浏览器 LocalStorage 保存当前探索；损坏则回到空白新探索；刷新后清除 loading。
- **密钥：** 不得写入 Git。生产通过环境变量配置：`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_REASONING_EFFORT`。
- **品牌：** 界面与文档使用 SIFT，不使用 Veribox 作为对外产品名。
- **性能体验：** 思考过程需可视化进度；对话不得无限转圈。

## 11. 技术基线（实现约束）

- Next.js App Router + TypeScript + Tailwind

## 12. 验收标准

v1 完成须同时满足：

1. 无 API Key 时示例 Brief 可走完整流程（Mock）
2. 有 Key 时 `/api/status` 为 `live` + 配置的模型名
3. Brief 分析后出现 Brief Card，可编辑
4. 确认后出现状态卡；已有想法可填词；暂无想法可直接出路线
5. 两种入口都得到正好 3 条路线，起点不同，最多 1 条推荐
6. 选路线后生成第一步平台计划；复制 / 打开 / 跳过 / 替换 / 更多来源可用
7. 返回上一步不丢失仍有效的 Brief / 状态
8. 画布对话基于选中卡片生成新分支，且不卡死（超时有提示，可取消）
9. 刷新后画布仍在
10. 模型报错不清空已有卡片
11. 仓库无密钥

回归 Brief 至少覆盖：护肤、包装、SaaS 视觉、餐饮、有明确想法、无明确想法、信息不完整或约束冲突。

## 13. 成功指标（产品）

定性（v1 验证用）：

- 从粘贴 Brief 到第一次打开带关键词的搜索，是否明显快于自己瞎搜
- 关键词是否可直接拿去 Pinterest / Behance / 小红书用
- 设计师下周是否还愿意再用

不考核：是否更好看、是否少做一版正式设计。

## 14. 后续版本（非 v1）

| 版本方向 | 内容 |
|----------|------|
| 收藏与反推 | 点选参考图后识别来源 / 风格名，再反搜 |
| 筛选报告 | 从大量收藏中归纳方向，仍由人勾选 |
| 槽位组合 | 风格 / 元素分槽，粗预览（非最终设计） |
| 垂直模板 | 包装感官框架、3–5 概念树等，作为可选模板而非主轴 |
| 协作 | 多人、评论、投票 |

后续任何能力仍须遵守：先改清「设计师原来怎么干」，再插 AI；一次只做一个可跑通的小圈。
